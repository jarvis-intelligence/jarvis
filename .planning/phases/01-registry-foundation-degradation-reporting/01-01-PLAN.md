<objective>
Persist failure state in the registry and explain it on the CLI — the tracer slice of Phase 1.

A hard-failed index run leaves a registry row carrying origin ('failed_hard'), a one-line reason, and the complete untruncated failure text; `jarvis status` explains what happened and how to recover; `jarvis list` marks repo health at a glance. Legacy registries migrate in place, additively.

Purpose: This is the foundation every other Phase 1 surface reads — without a persisted cause there is nothing to report (STAT-01, ROADMAP SC1/SC5).
Output: Extended `registry.py` (3 columns, `record_failure()`, origin taxonomy + `recovery_for()`), failure-recording hook in `index_repo()`, reporting in `_cmd_status`/`_cmd_list`, tests in `test_registry.py`/`test_index_cli.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| indexer subprocess → registry | external-tool stdout/stderr (attacker-influuable in theory via malicious repo content) is persisted verbatim into registry.db |
| registry → terminal | persisted stderr is re-displayed by `jarvis status` in the user's terminal |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `record_failure()` / `upsert()` SQL | medium | mitigate | All writes use parameterized `?` placeholders — the stderr/reason strings are data, never interpolated into SQL text (existing repo rule; RESEARCH security domain V5) |
| T-01-02 | Tampering | `_cmd_status` display | low | accept | Terminal escape sequences inside indexer stderr are the user's own toolchain output on a local single-user tool; D-02 locks verbatim persistence and display prints as-is with no shell interpolation anywhere |
| T-01-03 | Spoofing | origin slugs in registry rows | low | accept | Rows are written only by the local indexing pipeline; slugs are fixed constants, and read surfaces render them as data |
| T-01-SC | Tampering | package installs | high | accept | Zero package-manager installs in this phase (stdlib + pinned deps only; Package Legitimacy Audit in 01-RESEARCH.md installs nothing) — no supply-chain surface added |
</threat_model>
