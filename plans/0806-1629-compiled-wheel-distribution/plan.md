# Compiled-Wheel Distribution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Spec:** `docs/superpowers/specs/2026-08-06-compiled-wheel-distribution-design.md`
**Status:** pending

**Goal:** Future `jarvis-mcp` PyPI releases ship Cython-compiled `.so` modules with no readable Python source, while local dev stays pure Python.

**Architecture:** Replace the `uv_build` backend with setuptools whose `setup.py` cythonizes all `src/jarvis/` modules only when `JARVIS_COMPILE=1` (set by CI release builds). `publish-pypi.yml` becomes a 4-job pipeline: preflight tests → cibuildwheel matrix → wheel-content/handshake smoke → trusted publish. No sdist is ever built or uploaded.

**Tech Stack:** setuptools ≥ 80, Cython ≥ 3.1, cibuildwheel v3 (GitHub Action), uv, GitHub Actions, PyPI trusted publishing.

## Global Constraints

- Compile flag is exactly `JARVIS_COMPILE=1`; unset ⇒ pure-Python build (dev flow unchanged).
- Plain-Python allowlist in the wheel: exactly `jarvis/__init__.py` and `jarvis/scip_pb2.py`.
- Wheel matrix: cp312, cp313, cp314 × {linux x86_64, linux aarch64, macOS arm64, macOS x86_64}. Skip musllinux and Windows.
- Never build or publish an sdist.
- Dist name `jarvis-mcp`, import package `jarvis`, console scripts `jarvis` + `jarvis-server`, `requires-python = ">=3.12"` — all unchanged.
- Trusted publishing (OIDC, environment `pypi`, workflow file name `publish-pypi.yml`) must be preserved — the PyPI publisher config matches on these.
- Do NOT touch: setup.sh, plugin/, server.json, scripts/check_versions.py, the semantic extra's dependency list.
- Repo convention: comment-rich config/build files explaining WHY (match existing pyproject/workflow style).
- Conventional commits, no AI references.

- [ ] **Step 2: Create setup.py with conditional cythonize + source stripping**

```python
import os
from pathlib import Path

from setuptools import Extension, setup
from setuptools.command.build_py import build_py as _build_py

# scip_pb2.py is machine-generated from the public SCIP protobuf -- nothing
# proprietary -- and __init__.py is trivial. Everything else is compiled to a
# native extension when JARVIS_COMPILE=1 (set only by release CI) so published
# wheels carry no readable source. Dev installs never set the flag.
KEEP_PLAIN = {"__init__.py", "scip_pb2.py"}
COMPILE = os.environ.get("JARVIS_COMPILE") == "1"


class StripCompiledSources(_build_py):
    # build_py packages every .py it finds even when build_ext compiles the
    # same modules; without this override the wheel would ship source AND
    # binaries, defeating the point.
    def find_package_modules(self, package, package_dir):
        modules = super().find_package_modules(package, package_dir)
        if not COMPILE:
            return modules
        return [
            (pkg, mod, path)
            for pkg, mod, path in modules
            if Path(path).name in KEEP_PLAIN
        ]


if COMPILE:
    from Cython.Build import cythonize

    # Explicit Extension names: cythonize's dotted-name inference does not
    # understand src-layout and would emit `src.jarvis.query`.
    ext_modules = cythonize(
        [
            Extension(f"jarvis.{path.stem}", [str(path)])
            for path in sorted(Path("src/jarvis").glob("*.py"))
            if path.name not in KEEP_PLAIN
        ],
        compiler_directives={"language_level": "3"},
        nthreads=os.cpu_count() or 1,
    )
else:
    ext_modules = []

setup(ext_modules=ext_modules, cmdclass={"build_py": StripCompiledSources})
```

- [ ] **Step 3: Implement the checker**

Create `scripts/check_wheel_contents.py`:

```python
"""Assert release wheels ship compiled jarvis modules and no readable source.

The compiled-wheel pipeline can silently regress to publishing readable
source (JARVIS_COMPILE unset in CI, the build_py override dropped, a Cython
.c intermediate packaged by accident). publish-pypi.yml runs this over every
built wheel before upload; an empty report is the only green path.
"""

import sys
import zipfile

ALLOWED_SOURCE = {"jarvis/__init__.py", "jarvis/scip_pb2.py"}
SOURCE_SUFFIXES = (".py", ".pyx", ".pxd", ".c")


def check(wheel_path: str) -> list[str]:
    names = zipfile.ZipFile(wheel_path).namelist()
    problems = []
    compiled = [n for n in names if n.startswith("jarvis/") and n.endswith(".so")]
    leaked = sorted(
        n
        for n in names
        if n.startswith("jarvis/")
        and n.endswith(SOURCE_SUFFIXES)
        and n not in ALLOWED_SOURCE
    )
    missing = sorted(ALLOWED_SOURCE - set(names))
    if not compiled:
        problems.append(f"{wheel_path}: no compiled jarvis/*.so modules")
    if leaked:
        problems.append(f"{wheel_path}: readable source leaked: {leaked}")
    if missing:
        problems.append(f"{wheel_path}: missing expected files: {missing}")
    return problems


def main(argv: list[str]) -> int:
    if not argv:
        print("usage: check_wheel_contents.py <wheel> [<wheel>...]", file=sys.stderr)
        return 2
    problems = [problem for wheel in argv for problem in check(wheel)]
    for problem in problems:
        print(problem, file=sys.stderr)
    if problems:
        return 1
    print(f"{len(argv)} wheel(s) verified: compiled modules only")
    return 0


if __name__ == "__main__":
    raise SystemExit(main(sys.argv[1:]))
```

- [ ] **Step 1: Rewrite the workflow**

Replace the entire file with:

```yaml
# Publishes jarvis-mcp to PyPI on a GitHub Release, via trusted publishing.
#
# Wheels are Cython-COMPILED (cp312..cp314 x linux x86_64/aarch64 x macOS
# arm64/x86_64): the dev repo is private and the published artifact must not
# ship readable source, so `uv build`'s pure wheel is never uploaded and no
# sdist exists at all. scripts/check_wheel_contents.py is the guard that a
# build silently regressing to pure Python (JARVIS_COMPILE unset, build_py
# override dropped) fails before upload instead of after.
#
# Why trusted publishing: PyPI mints a short-lived token from the publish
# job's OIDC identity, so there is no long-lived API token to leak or rotate.
# That requires `permissions: id-token: write` and a matching publisher
# configured on PyPI (workflow file name publish-pypi.yml, environment pypi)
# -- renaming this file breaks publishing.
#
# The MCP Registry check: the official registry verifies PyPI ownership by
# finding an `mcp-name` marker in the published README. Losing that line
# breaks registry publishing long after the fact, so it is asserted here.
name: publish-pypi

on:
  release:
    types: [published]
  # Manual runs are safe: PyPI rejects re-uploading an existing version, so
  # the worst case is a loud failure in the publish job -- build and smoke
  # still validate the pipeline end-to-end.
  workflow_dispatch:

jobs:
  preflight:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: astral-sh/setup-uv@v5

      - name: Run the unit test suite
        run: |
          set -eu
          # Integration tests are excluded: they shell out to scip/zoekt/
          # scip-python, which setup-smoke.yml covers on real runners.
          uv sync
          uv run pytest -m "not integration" -q

      - name: Check the release tag matches the packaged version
        if: github.event_name == 'release'
        run: |
          set -eu
          packaged="$(uv version --short)"
          # Accept both `v0.2.0` and `0.2.0` tag styles.
          tagged="${GITHUB_REF_NAME#v}"
          if [ "$packaged" != "$tagged" ]; then
            echo "Release tag ${GITHUB_REF_NAME} does not match pyproject version ${packaged}." >&2
            echo "Bump the version in pyproject.toml, or retag the release." >&2
            exit 1
          fi
          echo "Version ${packaged} matches tag ${GITHUB_REF_NAME}"

      - name: Verify the MCP Registry ownership marker survived
        run: |
          set -eu
          marker='mcp-name: io.github.phuongddx/jarvis'
          if ! grep -qF "$marker" README.md; then
            echo "README.md is missing the registry ownership marker:" >&2
            echo "  <!-- $marker -->" >&2
            exit 1
          fi
          echo "Found the registry ownership marker"

  build-wheels:
    needs: preflight
    strategy:
      fail-fast: true
      matrix:
        # One native runner per platform: cibuildwheel does not cross-compile.
        os: [ubuntu-latest, ubuntu-24.04-arm, macos-latest, macos-13]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4

      - name: Build compiled wheels
        # Matrix, JARVIS_COMPILE=1, and the per-wheel unit-test run all come
        # from [tool.cibuildwheel] in pyproject.toml.
        uses: pypa/cibuildwheel@v3.2

      - uses: actions/upload-artifact@v4
        with:
          name: wheels-${{ matrix.os }}
          path: wheelhouse/*.whl
          if-no-files-found: error

  smoke:
    needs: build-wheels
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4

      - uses: astral-sh/setup-uv@v5

      - uses: actions/download-artifact@v4
        with:
          pattern: wheels-*
          merge-multiple: true
          path: dist

      - name: Verify every wheel ships compiled modules only
        run: python3 scripts/check_wheel_contents.py dist/*.whl

      - name: Smoke-test the compiled wheel against a fresh dependency resolve
        run: |
          set -eu
          # Installs from dist/ with dependencies resolved from PyPI and no
          # lockfile in sight, then requires a real MCP handshake -- the same
          # guard that caught 0.2.0's uncapped mcp range, now also proving
          # the compiled modules import and register on this platform.
          version="$(uv version --short)"
          uv venv "${RUNNER_TEMP}/smoke" --python 3.12
          uv pip install --python "${RUNNER_TEMP}/smoke/bin/python" \
            --find-links dist "jarvis-mcp==${version}"
          "${RUNNER_TEMP}/smoke/bin/python" - <<'PY'
          import json, os, subprocess, sys

          server = os.path.join(os.environ["RUNNER_TEMP"], "smoke", "bin", "jarvis-server")
          proc = subprocess.Popen([server], stdin=subprocess.PIPE, stdout=subprocess.PIPE,
                                  stderr=subprocess.PIPE, text=True, bufsize=1)

          def send(payload):
              proc.stdin.write(json.dumps(payload) + "\n")
              proc.stdin.flush()

          def expect(label):
              line = proc.stdout.readline()
              if not line:
                  proc.kill()
                  sys.exit(f"{label}: server produced no response\n"
                           f"stderr:\n{proc.stderr.read()}")
              return json.loads(line)

          send({"jsonrpc": "2.0", "id": 1, "method": "initialize",
                "params": {"protocolVersion": "2024-11-05", "capabilities": {},
                           "clientInfo": {"name": "publish-smoke", "version": "0"}}})
          print("initialize ->", expect("initialize")["result"]["serverInfo"])

          send({"jsonrpc": "2.0", "method": "notifications/initialized"})
          send({"jsonrpc": "2.0", "id": 2, "method": "tools/list"})
          tools = expect("tools/list")["result"]["tools"]
          proc.terminate()

          names = sorted(t["name"] for t in tools)
          # Guards against shipping a build that starts but registers nothing.
          if len(names) != 9:
              sys.exit(f"expected 9 tools, got {len(names)}: {names}")
          # FastMCP derives tool descriptions from server.py docstrings; a
          # compilation mode that strips docstrings would pass every other
          # gate and ship undocumented tools.
          undescribed = sorted(t["name"] for t in tools
                               if not (t.get("description") or "").strip())
          if undescribed:
              sys.exit(f"tools missing descriptions (docstrings lost?): {undescribed}")
          print(f"tools/list -> {len(names)}: {', '.join(names)}")
          PY

  publish:
    needs: smoke
    runs-on: ubuntu-latest

    # Must match the environment name on the PyPI trusted publisher. Also the
    # place to require a manual approval before any upload.
    environment:
      name: pypi
      url: https://pypi.org/p/jarvis-mcp

    permissions:
      # Required for PyPI trusted publishing. Nothing else needs write access.
      id-token: write
      contents: read

    steps:
      - uses: actions/download-artifact@v4
        with:
          pattern: wheels-*
          merge-multiple: true
          path: dist

      - uses: astral-sh/setup-uv@v5

      - name: Publish to PyPI
        run: |
          set -eu
          ls -la dist
          # No token: --trusted-publishing exchanges this job's OIDC identity
          # for a short-lived PyPI token. `always` fails loudly rather than
          # silently falling back to an unauthenticated upload attempt.
          uv publish --trusted-publishing always dist/*.whl

# One-time setup notes (trusted publisher, `pypi` environment, release tagging)
# are unchanged from the pure-wheel era -- see git history of this file.
```
